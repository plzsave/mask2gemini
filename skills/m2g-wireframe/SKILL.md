# mask2gemini ワイヤーフレームを実装資料として読む

## このファイルの正体

社内 Web アプリの実画面のスクリーンショットから、**秘匿情報（PII・業務データ）を
マスクした上で**画面構造だけを抽出した Excalidraw 形式（JSON）のファイル。
`"source": "mask2gemini"` を持つ。

重要なのは、これが**絵ではなくデータ**だということ。すべての抽出要素が
`customData.m2g` という意味のメタデータを持っており、
「この枠は何だったのか」が機械可読な形で入っている。

## 最初にやること: PNG に変換しない

`.excalidraw` を画像に変換して眺めたくなるが、**そうすると `customData.m2g` が
全部失われる**。役割・マスクの種別・要素種別・テーブルの列対応 —— 実装に必要な
情報はすべてメタデータ側にあり、絵には残らない。絵から読み取れるのは座標だけで、
座標はこのファイルで**最も信用してはいけない情報**（後述）。

**JSON としてそのまま読むこと。** ファイルが大きい場合は、同梱の
`scripts/summarize-wireframe.mjs` で全体像を先に把握するとよい:

```bash
# パスはこの skill のディレクトリからの相対
node scripts/summarize-wireframe.mjs <path-to.excalidraw>
```

既存構造と提案差分を仕分けして出力するので、生 JSON を全部読むより早く、
見落としも減る。

## 2 つの層に分かれている（これが差分の正体）

このファイルには性質のまったく違う要素が混ざっている。見分け方は 1 つだけ:

| | 意味 | どう扱うか |
|---|---|---|
| `customData.m2g` を**持つ** | mask2gemini が実画面から抽出した既存の画面構造 | **すでに実装されているもの**。文脈として読む |
| `customData.m2g` を**持たない** | 人間（または別の Agent）が Excalidraw 上で後から描き足した部分 | **これから実装すべき変更**。ここが差分 |

つまり **1 枚のファイルが、現状（v1）と変更提案（v2 差分）の両方を含んでいる**。

このため、実装の指示は「この画面を丸ごと作れ」ではなく
**「`m2g` を持たない要素を、既存構造への変更として実装せよ」**になる。
画面全体を再現しようとすると、すでに動いている部分まで作り直すことになり、
何が本当の変更だったのかも見えなくなる。

`m2g` を持たない要素が 1 つも無いファイルは、**まだ誰も編集していない撮影直後の
状態か、あるいは提案が「要素を増やす」以外の形で表現されている**。
どちらなのかはファイルからは判別できないので、実装に入る前に
「新規に描き足された要素が見当たらない」と報告して確認を取ること。

### この見分け方が効かない場合がある（重要）

Excalidraw で**既存要素を複製すると `customData` ごとコピーされる**。
そして m2g の規約は、データ枠を増やす提案について
「既存のマスク矩形の複製ベースで行うと意味が追従する」と**推奨している**。

つまり、推奨どおりに編集された提案（テーブルの行を増やす、入力欄を増やす等）は
**`m2g` を持ったまま増えており、上の表では既存構造に分類されてしまう**。
複製かどうかをファイルから機械的に見分ける方法は無い（複製元と同じメタデータを
持ち、`id` だけが違う）。

同じ理由で、**要素を増やさない形の提案も `m2g` の有無には現れない**:

- **削除**（「この列は要らない」）—— 消された要素はファイルに存在しないので、
  元の画面と見比べない限り分からない
- **移動・並べ替え**（「フィルタを上に」）—— 座標が変わるだけで、
  座標は規範ではない（次節）ため差分として読めない
- **複製**（データ枠・行を増やす）—— メタデータごとコピーされる

したがって:

- `m2g` の**有無**で確実に拾えるのは、新しく描かれた要素
  （新規のボタン・ラベル・枠・注釈の矢印）だけ
- それ以外の提案は、手順 3 で差分を提示する際に**構造の要約を根拠として一緒に示し、
  依頼者に確認を取る**（「テーブルの列は 申請番号 / 申請者 / 連絡先メール /
  承認ステータス の 4 つ」「メール入力欄が 2 つある」等）。
  同梱スクリプトの「テーブルの列ごとのデータ枠の数」の節はこの確認のためにある
- **矢印や線で「これをここへ」と指示されている場合がある**。矢印は結び先
  （`startBinding` / `endBinding`）に意味があるので、bbox だけを見て
  「よく分からない図形」として捨てないこと

推測で「これは複製された提案だろう」と判断しないこと。**数を見せて聞く**のが、
このファイル形式で取れる唯一の確実な方法。

## 何が規範で、何が規範でないか

ここを取り違えると品質が落ちる。このファイルの座標は**実画面の実測値**であって、
誰かが設計した寸法ではない。抽出の過程で数 px のズレも入る。

**規範として扱う（仕様）:**

- 要素が**存在すること**
- 要素の**順序**と上下左右の**位置関係**
- `groupIds` の `block-N` による**まとまり**（元画面のカード・セル等の単位）
- `role` / `kind` が示す**役割**（ナビゲーションなのか、テーブルヘッダなのか）
- `tableId` / `col` による**テーブルの列の対応**
- `decor` 要素が持つ**実測の配色**（`backgroundColor` / `strokeColor`）

**規範として扱わない（参考値）:**

- 絶対座標・幅・高さ・余白の具体的な数値
- `fontSize`（bbox の高さから逆算した近似値）
- 要素の厳密なピクセル位置

実装先のデザインシステムやコンポーネントの標準寸法が優先される。
**座標を再現するために既存のコンポーネントを歪めてはいけない。**
「ワイヤーと数 px 違う」は不具合ではない。「ワイヤーにある要素が無い」
「順序が違う」「列の対応が違う」が不具合。

## 手順

1. **JSON を読む**（必要なら `summarize-wireframe.mjs` で要約）
2. **2 層に仕分ける** —— `m2g` の有無で既存構造と提案差分に分ける
3. **差分を言葉にして提示し、数を添えて確認を取る** —— 実装に入る前に
   「何を変更すると読み取ったか」を箇条書きで示す。あわせて、複製ベースの提案は
   検出できない（前節）ため、**テーブルの列ごとのデータ枠の数・繰り返し要素の数**を
   一緒に示して依頼者に確認する。ワイヤーの解釈違いはここで潰すのが一番安い
4. **既存構造を手がかりに実装先を特定する** —— `role`/`kind`/テキストから、
   変更対象が実装コードのどこにあたるかを探す
5. **差分だけを実装する**
6. **報告する** —— 差分ごとに、実装した / 実装しなかった（理由付き）を対応させる。
   落ちたものが見えるようにするのが目的

## マスクされた枠（`role: "masked"`）の扱い

秘匿情報が入っていた場所で、**元の文字列はファイルのどこにも存在しない**
（そういう設計）。ハッチ塗りの矩形としてだけ現れる。

実装時は**ダミーデータを入れてよい**。種類の手がかりは 3 つ:

1. `reason` —— 何として判定して塗ったか（`email` ならメールアドレス、
   `digit-run` なら電話番号や金額や ID、`proper-noun` なら人名や組織名）
2. `kind` —— どの要素にあったか（`kind: "input:email"` ならメール入力欄）
3. **列ヘッダ** —— テーブル内なら、**同じ `tableId` かつ同じ `col` を持つ
   `role: "text"` または `role: "revealed"` の要素**（`kind` が `th` /
   `columnheader`）がその列の見出し。`revealed` を見落とさないこと。見出しが
   自動マスクされて人間が解除した場合、`text` ではなく `revealed` で出てくる。
   なお `kind: "th"` は行見出し（`<th scope="row">`）にも付くので、
   **見出し行（テーブル最上段）にあるものだけ**を列見出しとして扱う。
   「氏名」列の枠なら人名のダミー、「金額」列なら金額のダミー。
   これが一番確実な手がかり

マスク枠を「空欄」や「未実装」と解釈しないこと。**実画面にはデータが表示されて
いた場所**であり、実装でもデータが出る場所になる。

## 語彙の一覧

`role` / `reason` / `kind` / `v` の全語彙と読み分け規約は、同梱の
`references/m2g-schema.md` にある（リポジトリで作業している場合は
`docs/m2g-schema.md`）。一覧に無い値に出会っても**無視せず**
「そういう種別がある」として扱ってよい（前方互換のため、語彙の追加では
スキーマバージョン `v` は上がらない）。

## よくある誤り

- **PNG に変換してから読む** → メタデータが全部消える。JSON を読む
- **画面を丸ごと再現しようとする** → 差分だけを実装する
- **座標を仕様として実装する** → 位置関係と順序が仕様。数値は参考値
- **マスク枠を空欄として実装する** → データが表示される場所
- **`m2g` を持たない要素を無視する** → そこが最も確実な「やるべきこと」
- **列ヘッダを見ずにダミーを入れる** → `tableId` / `col` で結べる
- **`m2g` の有無だけで差分が全部拾えたと思う** → 削除・移動・複製は現れない。
  構造の要約を見せて確認する
- **矢印を「よく分からない図形」として捨てる** → 結び先に指示が入っている
